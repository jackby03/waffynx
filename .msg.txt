feat(sites): untrusted-input validator and nginx fragment renderer (SPEC-003 phase 1)

Phase 1 de SPEC-003. El spec quedo aprobado con las cinco decisiones
resueltas (generar y persistir el secreto JWT, solo fragmentos con include,
TLS por rutas de certificado, API como unico camino de escritura, y CLI
diferida). La sintaxis del CLI se aplaza entera, como pediste.

internal/sites es un paquete nuevo, puro: no hace I/O propio, asi que se
testea sin filesystem ni nginx. Depende de internal/config, nunca al reves.

Validacion (site.go):

- host: nombres DNS con etiquetas 1..63, wildcard '*.dominio' permitido,
  rechazo de IPs literales, de '..', de puntos al principio o al final, y de
  cualquier caracter de una lista explicita de inyeccion. Se RECHAZA, no se
  escapa: un host con ';' inyectaria directivas nginx.
- upstream: host:port o scheme://host:port con puerto obligatorio, sin
  credenciales, sin path, sin query. nginx defaultearia a 80 en silencio.
- tls: ambos ficheros obligatorios y sin caracteres de inyeccion en la ruta.
- paths: prefijo con barra inicial, sin '..' ni espacios, sin duplicados.
- Validate devuelve TODOS los problemas en una pasada (ValidationError con
  lista), para que el 400 del API sea accionable de una vez.
- ValidateSet ademas rechaza hosts duplicados normalizados.

Renderer (render.go): un server block por sitio, con las mismas directivas
que el nginx.conf que ya funciona. Un PathRule '/' define el upstream por
defecto y no emite un segundo location / (nginx lo rechazaria). /health va
con 'waffynx off' para que un sidecar caido no haga parecer el sitio caido
al orquestador. Salida determinista: sitios y headers ordenados.

Dos bugs que encontro la revision de los golden files, y que las aserciones
unitarias no veian:

1. Emitia 'listen :8443;' para sitios TLS, SIN la palabra ssl. nginx habria
   terminado la conexion como HTTP plano.
2. Emitia 'listen :8080;' cuando la forma probada es 'listen 8080;'.

Ambos corregidos en listenDirective, con test.
